# 경량화 RAG 아키텍처 및 모델 스택 리서치 (1B 중심)

## 1. 개요 및 배경
현재 `local-llm-gws` 앱의 주 타겟은 **저전력/저사양(8GB RAM, No GPU) 노트북 사용자**입니다. 
7B 이상의 고성능 모델은 RAM뿐만 아니라 **하드 디스크(SSD) 용량**을 크게 차지하므로(4~5GB 이상), 일반 사용자에게 기본 다운로드를 강제하는 것은 좋은 UX가 아닙니다. 

따라서 사용자가 원할 때만 고용량 모델을 선택하게 하고, **기본 제공(Default) 파이프라인은 하드 용량과 RAM을 최소한으로 차지하는 1B 내외의 모델들로 재편**해야 합니다. ChatGPT의 최신 연구 조사 결과를 반영하여, 0.5B ~ 1B 체급을 활용한 최적의 RAG 아키텍처를 재설계했습니다.

## 2. RAG 파이프라인에서의 역할 분담 (ChatGPT 리서치 반영)

초소형 모델(0.5B급)을 '최종 답변 생성용'으로 쓰면 앞서 언급된 환각이나 지시 무시 문제가 발생합니다. 하지만 이를 **RAG의 보조 부품**으로 사용하면 지연 시간과 용량을 획기적으로 줄일 수 있습니다.

### ❌ 피해야 할 구조 (단일 0.5B 모델 의존)
* `검색 -> 0.5B 모델에게 읽고 답하라고 지시 -> 환각/오독 발생`

### ⭕ 이상적인 경량 RAG 구조 (역할 분리)
1. **임베딩 (0.3B 이하)**: 문서 벡터화 (예: `multilingual-e5-small`) - 용량 100MB대
2. **리랭킹 (0.6B)**: 검색된 문서 중 진짜 중요한 것만 추려내기 (예: `Qwen3-Reranker-0.6B`) - 용량 약 600MB
3. **최종 생성기 (1B ~ 3B)**: 추려진 소량의 핵심 문서를 읽고 답변 작성 (예: `Gemma 3 1B` 또는 `Llama 3.2 1B`) - 용량 약 800MB ~ 2GB

## 3. 앱 기본 탑재용(Default) 추천 모델 스택

앱 설치 시 기본적으로 세팅되거나 권장할 수 있는 **'초경량 + 고품질' 하드 드라이브 친화적 스택**입니다. 전체를 다 받아도 2~3GB 수준으로 매우 가볍습니다.

### A. 최종 답변 생성기 (Generator)
환각을 줄이고 지시사항을 잘 따르려면 0.5B는 피하고 최소 1B 체급으로 올라와야 합니다.
* **1순위: `Gemma 3 1B IT`**
  * **용량**: 약 800MB ~ 1GB (Q4_K_M)
  * **선정 이유**: 중국어 리스크가 0%인 구글의 모델. 다국어 지원이 훌륭하고 1B 체급 중에서 RAG 문서 해석 능력이 뛰어납니다. 8GB 램 환경에서도 공기처럼 가볍게 돌아갑니다.
* **2순위: `Llama 3.2 1B Instruct` 또는 `3B Instruct`**
  * **용량**: 1B는 약 1GB, 3B는 약 2GB
  * **선정 이유**: 신뢰성 높은 서구권 모델. 3B의 경우 답변 품질이 급격히 좋아지면서도 여전히 저사양 노트북에서 구동 가능한 마지노선입니다.

### B. 검색 및 인덱싱 (Embedding & Reranker)
* **임베딩 (벡터 검색)**: `intfloat/multilingual-e5-small` 
  * 한국어를 지원하면서 극도로 가벼운 임베딩의 표준입니다.
* **리랭커 (정밀 검색)**: `Qwen3-Reranker-0.6B`
  * 생성(말하기)을 시키면 중국어가 나올 위험이 있지만, 리랭커는 **내부 점수(Score)만 계산**하고 끝내기 때문에 중국어 노이즈 문제가 전혀 발생하지 않습니다. RAG의 품질을 끌어올리는 최고의 부품입니다.

## 4. 결론 및 향후 구현 방향 (UX 제안)

1. **기본(Default) 설정**: 앱을 처음 켜는 사용자에게는 **Gemma 3 1B (또는 Llama 1B/3B) 중심의 초경량 스택**을 권장하여 하드 용량과 RAM 부담을 없앱니다.
2. **파워 유저(Opt-in) 옵션**: 7B 이상의 모델(EXAONE 3.0 등)이나 30B 모델은 설정 패널에서 "고품질 답변을 원하고 하드/램 용량이 충분한 사용자만 다운로드"하도록 경고 문구와 함께 별도 배치합니다.
3. **백엔드 고도화**: 장기적으로 `retriever.py` 로직을 개선하여 Qwen 0.6B 리랭커를 도입하면, 1B 생성기 모델에 던져주는 텍스트의 질이 좋아져서 최종 답변 품질이 7B 모델을 쓰는 것과 유사하게 향상될 수 있습니다.
